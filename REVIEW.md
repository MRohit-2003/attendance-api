# REVIEW.md — defects found in the starter `app/main.py`

I reviewed the starter like a pull request. Every defect below was fixed in the rewrite; the last column says how.

| # | Where | What is wrong | How you'd notice (test, input, symptom) | How it was fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds shift start with `punch_in.replace(...)`, i.e. in the punch-in's own (naive/local) timezone instead of IST. A 09:30 IST shift is compared against a UTC/local clock. | Punch in at 04:05 UTC (= 09:35 IST, shift 09:30): expected late 0, got late 300+. | `shift_window()` builds the shift start as a tz-aware IST datetime; all arithmetic is tz-aware. |
| 2 | `compute_late_minutes` | Grace check compares whole minutes `> 10`, so 09:40:01 counts as 0 instead of 10. | Punch 09:40:01, shift 09:30 → returns 0, must be 10 (R2 needs `> 600` seconds). | Compare `delta > 600` seconds, then `late = delta // 60`. |
| 3 | `compute_late_minutes` | No sub-second truncation, no overnight handling, and the start date is the punch date, not the attendance date. | Punch 09:40:00.900 → counts the 900ms; overnight shift 22:00–06:00 punch at 01:00 uses the wrong day's 22:00. | All instants truncated to whole seconds (R1); `attendance_date()` applies the overnight rule; late is computed against the shift window of the attendance date. |
| 4 | `compute_work_hours` | Uses `round()` — float/banker's rounding, not half-up — and never truncates microseconds; `half_day` is never computed anywhere. | 32562 s apart → `round()` gives 9.04 (banker's), contract needs 9.05 (half-up). | `Decimal(seconds)/3600` quantized `ROUND_HALF_UP`; `is_half_day()` applies R5 on the rounded value. |
| 5 | `compute_overtime` | No 30-minute minimum; overnight shifts get the wrong end (must be next day); `date_str` + naive `replace` is fragile; `max(0, int(...))` truncates toward zero instead of flooring. | Punch out 18:29 after an 18:30 end → `int(-60/60)` = -1 → `max(0,-1)` = 0 by luck, but 18:00:30 after end → `int(30/60)` = 0 hides real floor errors; any 1–29 min overtime is wrongly counted. | R3: floor minutes, negative → 0, counted only if `>= 30`; end from `shift_window()` (overnight-aware). |
| 6 | `create_employee` | Check-then-insert with no unique index: two concurrent duplicate creates can both pass the check. | 20 parallel creates with the same `emp_code` → more than one 201. | Unique index on `emp_code`; insert and catch `DuplicateKeyError` → 409. |
| 7 | `create_employee` | No validation at all (`emp_code` format, email, shift times, real `joined_on`, `shift_start != shift_end`); `created_at` is naive local `datetime.now()` and is returned as a datetime instead of epoch ms. | `POST /employees` with `emp_code: "xx"`, `email: "nope"`, `joined_on: "2026-02-30"`, `shift_start == shift_end` all return 201. | Pydantic validators (`re.fullmatch`, real-date check, model validator); `created_at` = UTC now truncated, returned as ms. |
| 8 | `list_employees` | `skip = page * page_size` (page 1 skips the first page); `total` ignores the department filter; no `emp_code` sort; no validation of `page`/`page_size`. | `GET /employees?page=1` misses the first 20 rows; `?department=X` reports the unfiltered total; `page=0`/`page_size=10000` accepted. | `skip = (page-1)*page_size`; `total` counts the filtered set; sort by `emp_code`; `Query(ge=1)`, `Query(ge=1, le=100)`. |
| 9 | `punch_in` | Unknown employee → `emp` is `None` → `emp["shift_start"]` raises `TypeError` → **500**. | `POST /attendance/punch-in` with unknown `emp_code` → 500, must be 404. | Explicit `None` check → 404 before any use of `emp`. |
| 10 | `punch_in` | `datetime.fromtimestamp(ms/1000)` uses server-local tz and naive datetimes; accepts seconds/floats/negatives; `if body.punched_at` is a truthiness check; `date` comes from the server tz, not IST; no overnight rule; no truncation. | `punched_at: 1700000000` (seconds) accepted; punch at 18:35 UTC with a 22:00–06:00 shift lands on the wrong attendance date. | `StrictInt` + range validation (422); `ms_to_dt()` → tz-aware UTC truncated to seconds; `attendance_date()` per R1; `is not None` check. |
| 11 | `punch_in` | Check-then-insert with no unique index on `(emp_code, date)`; `status` unvalidated (ABSENT/LEAVE/garbage accepted). | Two parallel identical punch-ins → two 201s; `status: "ABSENT"` on punch-in → 201. | Unique index + `DuplicateKeyError` → 409; `status: Literal["PRESENT","WFH","ON_DUTY"]` → 422 otherwise. |
| 12 | `punch_in` | Response leaks `id` (stringified `_id`) and returns `punch_in` as a datetime object, not epoch ms. | Response JSON contains `"id"` and `"punch_in": "2026-..."`. | Single `serialize_record()`; no `_id`/`id` anywhere; datetimes → ms. |
| 13 | `list_attendance` | Loads the whole collection into memory, sorts in Python by `date` only (missing the `emp_code` tiebreak), slices in Python; `page=0` gives a negative slice; no validation of page/page_size/status/dates; `date_from > date_to` not rejected; leaks `id`; datetimes not converted; legacy defaults missing. | 100k docs → multi-second responses and wrong order on ties; `?status=BOGUS` silently filters to nothing. | DB-side `.sort().skip().limit()` on an index, `count_documents` for total; full validation; `serialize_record()` everywhere. |
| 14 | `list_attendance` | Dates are not validated — garbage strings are compared as strings. | `?date_from=banana` returns 200 with silently wrong results. | Strict `YYYY-MM-DD` real-date validation → 422. |
| 15 | app setup | No indexes anywhere, no startup hook; `/health` never pings MongoDB (always "ok", never 503). | Kill MongoDB → `/health` still 200; every query is a COLLSCAN at 100k docs. | Named indexes created idempotently in the FastAPI lifespan; `/health` pings and returns 503 on failure. |
| 16 | `MongoClient` | Created without `tz_aware` (all datetimes come back naive) and without `serverSelectionTimeoutMS` (hangs instead of failing fast). | Punch-out arithmetic mixes naive/stale datetimes; `/health` hangs ~30s when Mongo is down. | `tz_aware=True, tzinfo=timezone.utc`, `serverSelectionTimeoutMS=5000`. |
| 17 | missing endpoints | punch-out, PATCH, all four analytics endpoints and explain are `TODO`. | — | Implemented per contract (see `app/main.py` sections 8). |
| 18 | `list_employees` projection | Uses `find(q, {"_id": 0})` — fine by itself, but inconsistent with the other endpoints which leaked `id`. | — | One serializer per shape (`serialize_employee`, `serialize_record`); `_id` never leaves the server. |
| 19 | error contract | Any unexpected `ValueError` (bad date strings, bad months) propagates as **500**. | `PATCH /attendance/EMP0001/banana` → 500. | Date/month parsing wrapped: `ValueError` → `HTTPException(422)` at every boundary. |

## Examined and judged NOT defects

- `load_dotenv()` with the default `override=False`: real environment variables already win over `.env` — correct as written.
- `PunchInIn.status` defaulting to `"PRESENT"`: fine once the value is validated against the allowed set (now a `Literal`, so anything else is 422).
- Returning `doc` after `doc.pop("_id")` in `create_employee`: hides `_id` correctly; the leak was the *added* `"id"` key in `punch_in`, which is a real defect (#12).
- The `/health` route path itself: correct; only its implementation was wrong (#15).
- `q["date"] = {}` when no date filters are given: harmless (matches nothing extra); kept the same shape in the rewrite for clarity.
- `extra="ignore"` on request models: required by the contract (derived/client-supplied fields must be ignored, not rejected).
